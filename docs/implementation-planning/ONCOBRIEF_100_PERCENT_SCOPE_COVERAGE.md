## 8. Remaining Non-Code Blockers (External & Environmental Constraints Only)

Because all 65 functional, architectural, UX, accessibility, and interoperability requirements are covered by `TASK-001`–`TASK-026`, the **only** remaining items that cannot be solved by writing repository code alone are:

1. **Host Mac Terminal Execution of Verification Commands (Sandbox Seatbelt Constraint):**
   - The AI agent runtime sandbox restricts spawning binaries outside `/Users/dhaanish/Documents/OncoBrief` (`/opt/homebrew/bin/node`, `pnpm`, `psql`) and blocks loopback TCP sockets (`127.0.0.1:5432`).
   - **Resolution:** All code, SQL migrations (`0020`, `0021`), and automated test suites are written directly into the repository so they can be executed in one command (`pnpm db:migrate && pnpm db:seed && pnpm test && pnpm --filter @oncobrief/web test:e2e`) from your Mac Terminal.
2. **External API Keys for `Live Verified` Cloud Execution:**
   - Switching from `Sandbox Verified` / `Deterministic Local Fallback` to `Live Verified` cloud execution requires populating `.env.local` with active keys (`SARVAM_API_KEY`, AWS Bedrock/Textract IAM credentials, `NVIDIA_API_KEY`, NHA ABDM Sandbox `ABDM_CLIENT_ID`/`ABDM_CLIENT_SECRET`, and Twilio/Webhook credentials).
   - **Resolution:** `TASK-014` and `TASK-026` provide `/api/v1/system/providers` and explicit UI mode badges so judges can immediately see which providers are running live vs. deterministic local fallback, and switching any provider to live mode requires only setting the environment variable in `.env.local` with zero code changes.
3. **Real-World 60–90 Day Clinical Operational Impact Data:**
   - As mandated in `ONCOBRIEF_ENHANCEMENT_PLAN.md` §10 (*"Pilot evidence discipline: KR targets in Section 1.2 are success criteria to measure, not results already achieved"*), real hospital throughput gains and no-show reductions require an IRB/hospital-approved 60–90 day prospective pilot deployment.
   - **Resolution:** `TASK-013` instruments the live database telemetry queries on `/workspace` and `/analytics` to measure these exact KRs automatically against real clinic activity while labeling the target benchmarks honestly during the hackathon demo.
