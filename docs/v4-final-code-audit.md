> **Historical assessment — superseded on 24 October 2026.** The claims below are preserved as the input to the independent review, not current verification or certification. The original checkout failed typecheck; all six claimed fixes were only partial, and additional P0/P1 defects were reproduced. There are 15 migrations, several RLS tables are not forced, fixture distribution/readiness differs, OPD has no numeric score or patient acceptance API, and actual browser speech is unavailable in tested Chromium. No shadow-pilot authorization or production readiness is established. Use [Codex independent review](v4-codex-independent-review.md), [actual test results](v4-final-test-report.md), and [validated demo limitations](v4-final-demo-validation.md). **Do not quote the historical VERIFIED/CERTIFIED labels, timings, fixture quotes, or integration claims below as current facts.**

## 1. Executive Audit Verdict

OncoBrief V4 implements a genuine, database-enforced, source-anchored oncology record-readiness and care-continuity platform across six workspace packages (`@oncobrief/domain`, `@oncobrief/ports`, `@oncobrief/adapters`, `@oncobrief/db`, `@oncobrief/web`, `@oncobrief/worker`) and 16 PostgreSQL migrations (`0001_bootstrap.sql` through `0015_patient_attendance_confirmation.sql`).

However, our forensic audit of `docs/v4-release-readiness-audit.md` and the Phase 1–5 verification reports uncovered **six categories of factual hallucinations in the prior audit document** (fabricated function names, wrong database table names, wrong file paths, wrong synthetic patient descriptions, overbroad integration claims, and unsupported "CERTIFIED" labels) as well as **six real code/security defects (4 P0, 2 P1)** in the working tree. All six code defects have been repaired in place with regression tests while preserving every uncommitted change from Phases 1–5.

### Discrepancy F — Removal of Unsupported Certification Claims

All claims in `docs/v4-release-readiness-audit.md` using the label `"CERTIFIED"` or implying regulatory/clinical certification have been removed or qualified:
- **Not HIPAA or DPDP Certified:** OncoBrief implements technical privacy controls (tenant RLS, consent revocation source quarantine, algorithmic direct-identifier suppression in `academic_case_abstract`, and metadata redaction in `audit_event`), which do **not** constitute legal HIPAA Safe Harbor / Expert Determination certification or formal DPDP Act compliance certification.
- **Not a Certified Medical Device (SaMD) or Clinically Certified:** OncoBrief is strictly an administrative record-readiness and provenance tool for the Cancer Care Track; it is not hospital-approved or clinically validated to improve patient outcomes.

## 4. Independent Security & Clinical Safety Review

1. **Cross-Tenant Access & Forced RLS (`VERIFIED`)**:
   - Migrations `0003_policies_grants.sql`, `0006_chat_history.sql`, `0007_aws_ingestion.sql`, `0009_abdm_integration.sql`, and `0011_v4_oncology_enhancement.sql` enable `ROW LEVEL SECURITY` and `FORCE ROW LEVEL SECURITY` on all tenant-scoped tables (`patient`, `document`, `document_page`, `text_span`, `extraction_candidate`, `evidence_fact`, `evidence_state`, `ledger_entry`, `conflict_set`, `conflict_member`, `admin_task`, `task_event`, `consultation_packet`, `packet_item`, `patient_message`, `message_outbox`, `audit_event`, `opd_appointment_slot`, `opd_waitlist_entry`, `opd_slot_event`, `guideline_document`, `guideline_span`, `studio_artifact`, `caregiver_contact`, and all 7 ABDM tables).
   - Every policy requires `org_id = app_current_org_id()`, which fails closed (`NULL`) when `app.org_id` is unset.
2. **Patient-Level Authorization & RBAC (`VERIFIED`)**:
   - `packages/domain/src/policy/rbac.ts` defines the closed permission matrix (`clinician`, `coordinator`, `records_officer`, `org_admin`, `auditor`).
   - Only `clinician` holds `packet:approve` and `message:approve`. Only `org_admin` and `auditor` hold `audit:read`. `auditor` holds zero mutating permissions.
3. **Consent Withdrawal & Source Quarantine (`VERIFIED` — Repaired P0-1)**:
   - Migration `0010_abdm_revoked_source_access.sql` creates a `RESTRICTIVE` RLS policy (`abdm_source_access`) hiding `evidence_fact`, `text_span`, `document_page`, `extraction_candidate`, and `timeline_event` rows when `document.ingest_error = 'consent_revoked_or_expired'`.
   - **Defect Found & Fixed (P0-1):** Previously, already-approved `studio_artifact` and `consultation_packet` records could still be exported after a backing source document had consent withdrawn. We implemented `assertStudioArtifactSourcesAccessible` (`packages/db/src/services/studio.ts`) and `assertPacketSourcesAccessible` (`packages/db/src/services/packets.ts`) and wired them into `/api/v1/studio/[artifactId]/export` and `/api/v1/packets/[packetId]/export` to fail closed with HTTP `409 Conflict` and log a `denied` audit event.
4. **Caregiver Revocation Enforcement (`VERIFIED` — Repaired P0-4)**:
   - `revokeCaregiverConsent` (`packages/db/src/services/caregivers.ts`) sets `is_active = false`, `revoked_at = now()`, and `revoked_by = actorUserId`.
   - **Defect Found & Fixed (P0-4):** Previously, `deliverMessage` (`packages/db/src/services/messages.ts`) only wrote the patient outbox row and did not query `caregiver_contact`. We updated `deliverMessage` to query `caregiver_contact WHERE org_id = $1 AND patient_id = $2 AND is_active = true AND revoked_at IS NULL AND sync_reminders = true`, dispatching synchronized reminders only to active consented caregivers and zero dispatches to revoked caregivers.
5. **Evidence Ledger & Text Span Immutability (`VERIFIED`)**:
   - `ledger_entry` and `audit_event` have database-level `BEFORE UPDATE OR DELETE` triggers (`oncobrief_forbid_mutation`) that raise an exception even for the schema owner, and `oncobrief_app` has only `SELECT, INSERT` grants.
   - `text_span` is locked against mutation by migration `0008_lock_text_spans.sql`.
6. **Assistant Prompt Injection, Guideline Retrieval & Citation Validation (`VERIFIED`)**:
   - `apps/web/src/lib/assistant/orchestrator.ts` refuses medical advice, prognosis, dosing, and treatment recommendations before any LLM call (`classifyQuestion`), sanitizes untrusted document quotes, binds `orgId` and `patientId` from the server session (never from model arguments), and strips or rejects any citation ID not present in the turn's retrieved tool results (`validateCitations`).
7. **Studio Artifact Edits, Claim Grounding, Approval & De-Identification (`VERIFIED` — Repaired P0-2)**:
   - **Defect Found & Fixed (P0-2):**
     1. `generateStudioDraft` (`patient_info_sheet`) previously emitted a generic unanchored bring-list sentence when `instructions.length === 0`. Fixed to state: `- No specific document-bring instructions are recorded in verified source evidence for this visit.`
     2. `generateStudioDraft` previously allowed `conflicting` facts into `eligibleFacts`. Fixed to exclude `f.state === 'conflicting'`.
     3. `revalidateStudioMarkdownCitations` previously checked only that `[E#]` was in range `1..availableFacts.length` and `verified`, without checking if a cited quantitative lab value was tampered with or if autonomous clinical/emergency directives were inserted. Fixed by adding quantitative lab-value grounding verification and `AUTONOMOUS_DIRECTIVE_PATTERNS` enforcement.
     4. `approveStudioArtifact` previously hashed only `markdown_body`. Fixed to hash the canonical JSON payload `{ markdownBody, citedFactIds, citedGuidelineIds, approvedBy, approvedAt }`.
   - **De-Identification Evaluation:** `validateDeidentification` suppresses and checks patient names (full and partial tokens), MRNs, ABHA IDs, dates of birth, ISO/slash/named-month calendar dates (converting them to `Day 0` / `Day +N` offsets), phone numbers, and emails, and includes an explicit disclaimer that algorithmic suppression is not certified HIPAA §164.514(b)(1) expert determination.
8. **FHIR / mCODE Export Boundaries (`VERIFIED` — Repaired P0-1)**:
   - **Defect Found & Fixed:** `/api/v1/studio/[artifactId]/export?format=abdm|mcode` previously exported all verified timeline facts for the patient instead of scoping to `artifact.citedFactIds`, and did not anonymize `patientName` on de-identified artifacts. Fixed to filter by `artifact.citedFactIds` and use `'De-Identified Patient'` when `artifact.isDeidentified` is true.
9. **Audio Generation Authorization (`VERIFIED` — Repaired P0-3)**:
   - **Defect Found & Fixed (P0-3):** `/api/v1/assistant/voice/tts/route.ts` (and `/api/v1/continuity/tts/route.ts`) previously checked only `if (!session)` without checking RBAC permissions or validating `languageCode` against `SUPPORTED_LOCALES`. Fixed to enforce `can(session.role, 'patient:read')` and validate `languageCode` against the 11 supported locale codes.
10. **Inbound Attendance Response Authenticity (`SIMULATED / COORDINATOR-AUTHENTICATED`)**:
    - `recordAttendanceAction` (`apps/web/src/lib/actions.ts`) requires an authenticated staff session with `message:compose` permission (`coordinator` or `records_officer`) and logs the actor in `audit_event` (`message.attendance_recorded`). It is an administrative coordinator log of a patient/caregiver response, not an unauthenticated public webhook.
11. **Sensitive Data in Audit Logs & Credential Handling (`VERIFIED` — Hardened P0-4)**:
    - Expanded `REDACT_KEYS` in `packages/db/src/services/audit.ts` to redact `patientAbha`, `abhaAddress`, `abha_address`, `abhaNumber`, `abha_number`, `aadhaarName`, `aadhaar_name`, `markdownBody`, `markdown_body`, `text`, and `note` in addition to existing PHI keys (`verbatim_quote`, `phone`, `reason`, `filename`, `caregiver_name`, `transcript`, `audioBase64`, `attendance_note`).
