# V4 Phase 2 execution checklist

Specification: root `ONCOBRIEF_ENHANCEMENT_PLAN.md` section 7, tasks 2.1–2.3; ADRs 0019–0021; AGENTS.md rules.

## Step A: Audit & Mapping

1. **Task 2.1 — Oncology Demo Data & Readiness**:
   - Seed `DEMO-001` (Breast Oncology): referral, pathology/IHC, surgery, serial CBCs on different dates, previous consultation baseline (`last_consultation_date`), newly received reports, pending IHC/slides, documented instruction to bring prior records.
   - Seed `DEMO-002` (Medical Oncology): chemotherapy administration records as written, dated labs, follow-up events, missing document / explicit instruction, previous consultation baseline.
   - Seed `DEMO-003` (Radiation Oncology): radiation completion documentation, follow-up reports, chronological events, approved reminder, previous consultation baseline.
   - 3 Oncology checklist templates: `ncg_oncology_intake`, `ncg_tumor_board_prep`, `ncg_oncology_followup`.
   - Seed fixtures for later phases: `opd_appointment_slot`, `opd_waitlist_entry`, `guideline_document`, `guideline_span` (synthetic institutional SOPs, clearly labeled, non-fabricated geometry and sha256).

2. **Task 2.2 — Consultation Readiness Experience**:
   - `verifyEvidenceBatch` in `packages/db/src/services/ledger.ts`: server-side eligibility check (OCR confidence >= 0.90, correct tenant/patient, not in open conflict, not rejected/superseded/stale, source accessible), atomic transaction, individual ledger entries, batch audit event, readiness recomputed, fails closed on any invalid item.
   - `verifyEvidenceBatchAction` in `apps/web/src/lib/actions.ts`: RBAC check (`evidence:verify`), caller session, validation, revalidation.
   - Upgrade `apps/web/src/app/(app)/patients/[id]/evidence/page.tsx`:
     - Guided readiness banner with real blocker links (Reconciliation Room, Record Map, batch verify).
     - "Changes Since Last Consultation" banner with real counts from `getLongitudinalReview` (new documents, new/updated facts, new/reopened conflicts, pending investigations/instructions).
     - Filters: All, Since last consultation, Unverified, Conflicting, Verified, Longitudinal labs, Medication history.
     - Longitudinal lab flowsheet table with test name, date, value as written, previous vs latest, safe arithmetic delta, state, source links.
     - Medication history table/view chronologically as written.
     - Batch verification review modal with deselect, quote preview, source doc/page, and atomic submit.
   - Accurate timeline labels in `TimelineNodeView.tsx`: remove "Apollo Hospitals" and "CT Scan (Thorax)" fallbacks; map actual oncology modalities and facilities.

3. **Task 2.3 — Real ABDM/mCODE Bundle Import UI**:
   - Upgrade `apps/web/src/components/DocumentUploadForm.tsx`:
     - Replace alert-only UI with working server actions.
     - `importStandardBundleAction`: Accepts valid FHIR R4 JSON bundle (NRCeS ABDM / mCODE), validates bundle format, creates `fhir_document` via `createDocument`, ingests via `ingestDocument`, extracts facts into ledger, enforces authorization and tenant isolation, reports real errors.
     - `linkExistingDocumentAction`: Secure linking of existing unattached/duplicate documents without cross-patient or cross-tenant leaks.
